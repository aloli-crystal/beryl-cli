= Local test VMs for beryl
:toc: left
:toc-title: Table of Contents
:toclevels: 3
:source-highlighter: rouge
:icons: font

This directory provides tools to *automatically* create a local VM that
simulates a hosting provider's Linux rescue environment, so you can test
`beryl bootstrap` without depending on OVH or Scaleway.

The VM descriptor is a *YAML file* — readable, version-controlled, easy
to duplicate — and the `launch.sh` script uses it to drive QEMU.

== Prerequisites

Install QEMU and yq via Homebrew:

[source,sh]
----
brew install qemu yq
----

Download the Debian 13 live ISO (~1 GB) into `~/iso-linux/`:

[source,sh]
----
mkdir -p ~/iso-linux
curl -fLo ~/iso-linux/debian-live-13.4.0-amd64-standard.iso \
  https://cdimage.debian.org/debian-cd/current-live/amd64/iso-hybrid/debian-live-13.4.0-amd64-standard.iso
----

== Launch the VM

From the beryl project root:

[source,sh]
----
./examples/local-test-vm/launch.sh examples/local-test-vm/debian-rescue.yml
----

First run:

. A virtual disk `~/vms/debian-rescue.qcow2` is created (40 GB sparse, ~200 KB actual until filled).
. QEMU opens a Cocoa window booting the Debian live ISO.
. Host port 2222 is forwarded to VM port 22.

== Prepare the Debian rescue — automated path

Clipboard does not work in the QEMU cocoa window. beryl provides a
`prep-rescue` subcommand that works around this: it serves your SSH
public key and a provisioning script over local HTTP, so the operator
only needs to type one short line in the VM.

**Terminal 1 (on your Mac, keep it open during the operation):**

[source,sh]
----
cd ~/prod-crystal/crystal-beryl
./bin/beryl prep-rescue
----

Displays:

....
In the VM (Debian/Ubuntu Linux rescue), type this single line:

    curl -fL http://10.0.2.2:8080/s | sudo sh

Ctrl+C to stop the server.
....

**In the QEMU window** (Debian live VM, as user `user`, password `live`),
type the suggested line:

[source,sh]
----
curl -fL http://10.0.2.2:8080/s | sudo sh
----

The script:

. installs `openssh-server` and `curl`,
. fetches your public key from the beryl server,
. appends it to `/root/.ssh/authorized_keys`,
. enables `PermitRootLogin yes` and starts sshd.

Duration: ~10–30 s depending on apt bandwidth.

**Verify from your Mac:**

[source,sh]
----
ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null \
  root@localhost uname -a
----

Expected: `Linux ... GNU/Linux`.

Ctrl+C in the beryl server terminal to stop it once SSH works.

=== `beryl prep-rescue` options

[cols="1,3"]
|===
| Option | Description

| `--port PORT` | Local HTTP port (default: `8080`).
| `--bind ADDR` | Bind address (default: `127.0.0.1`).
| `--pubkey FILE` | SSH public key file (default: `~/.ssh/id_ed25519.pub`).
|===

For a **remote** rescue (OVH, Scaleway): replace `10.0.2.2` with your
workstation's public IP and make sure the port is reachable (open it
in your firewall if needed). The flow: rescue → HTTP → operator host.

== Declare the VM in beryl

Add it to your `inventory.yml`:

[source,yaml]
----
hosts:
  localhost:
    provider: generic
    port: 2222
    user: root
----

Identify the virtual disk as seen *from inside the VM*:

[source,sh]
----
ssh -p 2222 root@localhost "lsblk -dno NAME,TYPE,SIZE | awk '\$2==\"disk\"'"
----

Expected: `vda  disk  40G` (virtio-blk exposes disks as `/dev/vda`).

== Run the beryl bootstrap

[source,sh]
----
./bin/beryl -i inventory.yml bootstrap localhost --disk=/dev/vda
----

The bootstrap:

. Downloads the mfsBSD image from `depenguin.me`.
. Writes it to `/dev/vda` via `dd` (the virtual disk — no risk to your Mac).
. Reboots the VM into mfsBSD.
. Installs FreeBSD 15 as pkgbase on ZFS.
. Reboots into the installed system.

The QEMU window shows each boot phase.

== Variants and extensions

=== Ubuntu Server instead of Debian

Duplicate `debian-rescue.yml` as `ubuntu-rescue.yml` and point `iso:`
at `~/iso-linux/ubuntu-24.04.4-live-server-amd64.iso`.

=== Headless mode

Change `display: gui` to `display: none` in the YAML and connect via SSH
only. Useful for a future local CI.

=== Serial mode for debugging

`display: serial` attaches stdio to the serial console: full boot log
in your terminal (handy if the VM window doesn't open).

=== Multiple concurrent VMs

Each VM must have a unique `ssh_port_forward` (2222, 2223, 2224…) and a
distinct `disk.image`.

== Known limitations

* *Apple Silicon + x86_64*: QEMU emulates, 5–10× slower than native.
  Fine for a one-off bootstrap test; for fast iteration, test first with
  an `aarch64` VM (change `arch:` in the YAML and use an ARM64 Debian ISO).
* *No KVM/HVF acceleration* for x86_64 on ARM Macs. A QEMU limitation,
  not a beryl one.
* *UTM as a GUI alternative*: UTM can open the same qcow2 disk if you
  prefer its window to QEMU's Cocoa window (useful for clipboard sharing).

== Cleanup

[source,sh]
----
rm -f ~/vms/debian-rescue.qcow2    # destroys VM state
----

To start fresh, the launcher recreates a clean disk on the next run.
