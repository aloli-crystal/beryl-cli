= Exemple d'inventaire beryl en mode arborescent

Au lieu d'un seul fichier `inventory.yml`, l'inventaire est éclaté en :

* `groups/*.yml` — valeurs par défaut pour un groupe de serveurs.
* `hosts/*.yml` — un fichier par serveur (le nom du fichier = nom de
  l'hôte, ex. `hosts/loulou.aloli.net.yml`).

Chaque hôte peut lister les groupes dont il hérite dans son champ
`groups:` (ordre = priorité croissante, dernier écrit gagne). Ses
propres champs s'appliquent en tout dernier.

== Usage

[source,sh]
----
beryl -i examples/inventory-tree list-hosts
beryl -i examples/inventory-tree show loulou.aloli.net
beryl -i examples/inventory-tree bootstrap loulou.aloli.net
beryl -i examples/inventory-tree apply loulou.aloli.net
----

== Règles de merge

*Scalaires* (hostname, raid, swap_gb, timezone…) : le plus spécifique
gagne (host > dernier groupe > premier groupe).

*Hashes imbriqués* (`freebsd:`, `ovh:`) : merge récursif champ par
champ.

*Listes* — comportement dépendant du chemin, dicté par le cas d'usage
« installation standard en groupe + personnalisation par host » :

[cols="1,3", options="header"]
|===
|Chemin YAML | Comportement

|`freebsd.packages`
|*Append + dédup.* Le groupe fournit la base (ruby, zsh, postgresql),
 le host ajoute ses spécificités (nginx, redis). Les doublons sont
 repliés.

|`freebsd.sudoers`
|*Append + dédup.* Même logique.

|`freebsd.users`
|*Merge par `name:`.* Le host peut redéfinir un user existant du
 groupe (ex. changer les ssh_keys de `admin`) sans devoir recopier
 toute la liste. Un nouveau nom de user est ajouté.

|`freebsd.disks`
|*Override.* Les disques sont par nature spécifiques à un serveur,
 jamais définis utilement dans un groupe.

|Toute autre liste
|*Override.* Sûr par défaut.
|===

== Arborescence

[source]
----
examples/inventory-tree/
├── groups/
│   ├── aloli-admin.yml      # users admin standard (clés SSH à personnaliser)
│   ├── rails-servers.yml    # stack Rails (ruby, postgresql, nginx)
│   └── backup-servers.yml   # stack backup (rsync, restic, borg)
└── hosts/
    ├── loulou.aloli.net.yml # hérite aloli-admin + rails-servers
    └── backup01.aloli.fr.yml # hérite aloli-admin + backup-servers
----

== Clés SSH

Le fichier `groups/aloli-admin.yml` contient une clé SSH placeholder.
**Remplacez-la par la vôtre** avant tout bootstrap. Pour un cas ponctuel
avec une clé différente sans modifier le YAML, utilisez
`beryl bootstrap --authorized-keys=~/.ssh/ma-cle.pub`.

La règle Aloli interdit les défauts silencieux : si un user n'a aucune
clé dans le YAML et qu'aucun `--authorized-keys` n'est passé, `beryl`
refuse de démarrer avec un message explicite.
