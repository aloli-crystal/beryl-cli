[.lead]
Liste des hébergeurs proposant à la location des serveurs *physiques complets* (bare metal / dédiés), et non des machines virtuelles, avec une *API publique de gestion*.

IMPORTANT: Les prix et caractéristiques sont susceptibles d'évoluer. Référez-vous toujours au site officiel de chaque prestataire pour les informations à jour. Les informations ci-dessous sont valables en avril 2026.

== Critères retenus

* Location de serveurs *bare metal* (matériel physique entièrement dédié au locataire, sans hyperviseur imposé).
* *API publique documentée* permettant au minimum le provisioning, le reboot, la réinstallation OS, la gestion réseau.
* Sont exclus les VPS, instances virtualisées et offres uniquement via ticket/courriel.

== Cas particuliers et points d'attention

=== Equinix Metal : fin de service

[WARNING]
====
*Equinix Metal* était historiquement la référence du bare metal API-first (plateforme Packet rachetée par Equinix). Equinix a annoncé la *fin commerciale* du service : plus de nouvelles ventes, et *sunset complet au 30 juin 2026*. Ne pas démarrer de nouveau projet sur cette plateforme.

Les alternatives les plus souvent citées pour une migration sont *Latitude.sh*, *Cherry Servers*, *PhoenixNAP*, *Vultr Bare Metal* et *Hetzner*.
====

=== Frontière bare metal / cloud

La distinction est parfois floue :

* *Bare metal classique* (OVH Rise, Hetzner dédiés, Dedibox) : livraison en minutes à heures, facturation mensuelle, très compétitif en prix.
* *Bare metal cloud* (Scaleway Elastic Metal, PhoenixNAP BMC, Latitude.sh, AWS `*.metal`, Vultr Bare Metal) : provisioning API en secondes/minutes, facturation horaire, intégration cloud-native.

Les deux modèles sont du bare metal au sens strict — un seul locataire sur le matériel physique — mais le second est plus agile et mieux adapté aux workflows IaC modernes.

== Sources et vérification

Pour vérifier la présence effective d'une API chez un prestataire, cherchez sur son site :

* Une section `/developers`, `/api`, `/docs/api`.
* Un provider Terraform officiel sur le registry HashiCorp.
* Un SDK officiel sur GitHub (organisation du prestataire).

[TIP]
====
Pour votre usage avec Crystal, la plupart de ces API étant des REST JSON standard, vous pouvez les consommer directement avec la stdlib `HTTP::Client` + `JSON.parse`, ou via des shards génériques. À ma connaissance, aucun SDK Crystal officiel n'est fourni par ces prestataires — il faut soit consommer l'API en direct, soit wrapper un SDK existant.
====
